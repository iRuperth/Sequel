# Sequel

Sequel is a SQL training platform built like the internal data platform of a large data company. You get a query workbench on a sandboxed warehouse with realistic company datasets, a data catalog, tickets written by stakeholders and generated by an LLM, automated grading, code review, progress tracking, dashboards, scheduled queries and data quality checks.

## Quick start

Requirements: Docker, Node.js 22 or newer, pnpm 10.

```bash
make dev
```

`make dev` creates `.env` from `.env.example` if it is missing, installs dependencies, starts Postgres and Redis in Docker, bootstraps database roles, runs migrations, loads the warehouse datasets on first run and starts the web app, API and worker with hot reload.

| Service       | URL                               |
| ------------- | --------------------------------- |
| Web           | http://localhost:3030             |
| API           | http://localhost:4040/api/v1      |
| API reference | http://localhost:4040/api/v1/docs |
| Worker health | http://localhost:4041/health      |

To generate tickets with Claude, set `LLM_API_KEY` in `.env`. Without a key, set `LLM_PROVIDER=mock` to use the built in exercise bank.

## Architecture

```
apps/
  web/        Next.js App Router frontend
  api/        Fastify REST API, Server-Sent Events for job progress, OpenAPI
  worker/     BullMQ workers: ticket generation, grading, code review, schedules, quality checks
  cli/        Operational commands: bootstrap, migrate, seed, setup
packages/
  config/     Zod validated environment configuration
  contracts/  Zod schemas and types shared by every app, API route table
  copy/       All user facing text
  db/         Drizzle schema and SQL migrations for the application database
  sql-engine/ Postgres parser based policy, sandboxed runner, EXPLAIN mapping, result grader
  llm/        Provider interface, Anthropic provider, mock provider, prompts
  queue/      Queue names, job payload schemas, producer
  datasets/   Warehouse DDL, deterministic data generator, catalog docs, starter exercises, seeds
  core/       Application services used by the API, worker and CLI
docker/       Compose file and production Dockerfiles
k8s/          Kustomize base with local and prod overlays
tests/        Integration tests against the dockerised Postgres
```

Two Postgres databases run in the same instance. `sequel_app` stores platform metadata. `sequel_sandbox` is the warehouse, with one schema per dataset. User SQL runs with dedicated roles:

- `sequel_sandbox_reader` runs read only queries with role level timeouts and no write grants.
- `sequel_sandbox_writer` owns personal `scratch_*` schemas for DDL and DML practice and can only read shared datasets.
- Every statement is parsed with the real Postgres parser, checked against a per mode allowlist and function denylist, executed in a transaction with `statement_timeout`, cursor based row limits, byte limits and a watchdog that cancels runaway backends.

## Commands

| Command                                      | Purpose                                             |
| -------------------------------------------- | --------------------------------------------------- |
| `make dev`                                   | Full local environment with hot reload              |
| `make up` / `make down`                      | Start or stop Postgres and Redis                    |
| `make setup`                                 | Bootstrap roles, migrate and seed when empty        |
| `make seed-force`                            | Reload datasets, catalog, starter tickets and seeds |
| `make reset`                                 | Remove containers and volumes                       |
| `make lint` / `make typecheck` / `make test` | Static checks and unit tests                        |
| `make test-integration`                      | Integration tests against Postgres                  |
| `make build` / `make docker-build`           | Build apps and production images                    |
| `make app-up`                                | Run the whole stack from production images          |
| `make k8s-apply K8S_ENV=local`               | Deploy to a local cluster with Kustomize            |

## Conventions

- Configuration comes from environment variables validated at startup. Nothing environment specific lives in code.
- User facing text lives in `packages/copy`.
- Source files contain no comments; the lint rule `sequel/no-comments` enforces it.
